# Eval Studio v1 使用教程

本工具评测你已经准备好的内容，不负责生成待评测数据。分析工作在导出后进行，这里提供配置、执行、基本预览和导出。

[TOC]

## 1. 创建和打开项目 {#projects}

先在“项目”页点击“新建项目”，填写名称和可选说明，保存后点击“打开”。首次不会自动创建默认项目。

一个项目可以包含多个数据集、标准方案、评测器和运行。例如同一工作主题下的不同评测方案可以都放在这个项目，依靠名称、ID、时间和版本区分。项目之间的业务记录不能相互引用或移动；模型连接全局共用。

顶部项目选择器可以切换。未保存的字段、标准或评测器修改会提示是否放弃；切换后恢复该项目最近选择的保存对象。正在后台执行的任务不因切换而取消，返回原项目仍可查看。

项目列表可查找名称或说明、修改项目名称和说明。归档后默认隐藏，勾选“包含已归档项目”可查看和恢复。归档项目仅供查看历史和导出，恢复后才能编辑或执行。

永久删除先展示对象、版本和文件数量，再要求输入项目名称。它会整体清理项目业务记录与所属文件。项目内部的引用不会阻止整包删除，但未结束的运行或设计调用会阻止删除及归档。外部原始资料、其他项目、全局模型配置和旧数据库不在删除范围内。

## 2. 导入数据和选择评测字段 {#data}

打开项目后，在“数据与字段”选择文件，确认导入。支持 UTF-8 JSONL、JSON、XLSX，最大 25 MB，不支持 CSV。

| 格式 | 内容要求 |
| --- | --- |
| JSON | 单个对象或对象数组，每个对象是一条记录 |
| JSONL | 每个非空行是一个 JSON 对象 |
| XLSX | 选择工作表和表头行；表头不能为空或重复 |

工作台保存导入副本、原始记录、文件 SHA256、源行号和稳定内部行 ID。数据集记录不会因刷新或重启消失。同名上传通过时间和 ID 区分，不覆盖已有数据。

嵌套对象和数组保留原结构，数组不自动拆成新记录。XLSX 中的 JSON 文本不自动猜测成对象，公式按文本保存，不执行公式。

“参与评测的字段”决定哪些材料进入 Judge 和依据分析。全部标准共同使用这些字段，不需要区分任务输入、已有输出或参考角色。

字段路径是 JSON Pointer，不是电脑文件路径：

```json
{"record_id":"A01","task":{"question":"问题"},"answer":"已有回答","reference":"核对资料","internal_note":"仅供内部分析"}
```

| 路径 | 读取位置 |
| --- | --- |
| `/task/question` | task 对象里的 question |
| `/answer` | 已有回答 |
| `/reference` | 核对资料 |

字段名中的 `~`、`/` 在路径中分别写为 `~0`、`~1`。选择父对象时，其子内容整体参与评测。

勾选需要的字段并“保存字段配置”，产生配置版本。未选中的原始列不会自动发送给模型，但默认仍会随结果导出。修改勾选后必须保存，旧运行的字段快照不受影响。

同一数据集需要另一套字段清单时，点击“新建字段配置”，另存为独立对象；也可在下拉框选择已有配置。编辑已有配置后保存则产生该对象的新版本。

## 3. 配置标准和可选依据分析 {#standards}

没有生成任务 Prompt 时，直接填写标准即可。标准提取是可选路径：粘贴或读取原生成任务 Prompt 后点击“调用模型提取候选”，会发起真实请求并替换当前标准草稿。它不执行生成任务，候选仍需要人工编辑确认。

| 配置 | 含义和影响 |
| --- | --- |
| 标准 ID | 如 C001，关联返回结果，版本间尽量保持相同含义 |
| 名称 | 简短说明判断什么 |
| 描述 | 写清合格条件、判断范围、边界和依据不足时的处理 |
| 启用 | 关闭后本次不执行该标准 |
| 评测方式 | LLM 内容判断、程序非空或程序 JSON Schema |
| 程序作用字段 | 必须属于当前共同评测字段，只作用于该字段 |
| 设计备注 | 随版本保存的思路记录，不进入请求或判定 |

LLM 标准适合语义、任务符合性等判断；程序规则适合确定的内容存在性和结构校验，不调用模型。两种结果分别标明来源。描述不会被转换成任意可执行代码。

保存标准产生新版本，不自动修改已有评测器绑定。后续修改标准后，应重新构建并保存评测器。

依据分析在保存字段配置和标准后使用一条预览样本。程序显示字段是否缺失或为空，模型提供建议。字段存在不保证依据正确或充分；建议也不是审批结果，不强制执行该步骤。

提取和分析先保存成“设计调用”，成功、失败均可在项目历史查看。保存标准时关联对应调用；分析后再保存标准可记录这次关联。原始生成 Prompt 不会自动追加到 Judge 请求。

## 4. 编辑评测器消息与返回结构 {#evaluator}

保存标准后点击“按标准构建草稿”，产生确定性的默认模板，不会为构建模板调用模型。评测器绑定指定标准版本，保存后单独产生版本。

同一标准需要另一套独立评测器时，先点击评测器选择框旁的“新建”，再构建并保存；否则重新构建当前评测器会保存为其新版本。

System 和 User 展示实际模板，模板外不会再追加隐藏消息。三个变量必须出现，未知变量报错：

| 变量 | 实际内容 |
| --- | --- |
| `{{criteria}}` | 启用的评测标准 |
| `{{fields}}` | 当前样本的全部共同评测字段 |
| `{{response_schema}}` | 评测返回 JSON Schema |

默认 System 写裁判要求、标准和返回结构；User 写材料。替换只执行一次，不执行字段内容中的占位符或代码。要判断的内容应作为资料处理，不能把样本里的指令当作工作台指令。

保存后选择一条“消息预览 / 依据分析样本”，点击“预览实际消息”查看完整 System/User 内容，不发送请求。即使尚未配置模型，也可以静态预览消息。原始 HTTP 请求体和公开模型参数放在折叠区。

“预期输出结构示例”仅帮助理解返回格式，不是模型结果或正确答案。常见 Schema 可自动生成；复杂结构可在高级区手动填写，保存时本地校验。

高级区提供返回 Schema 和结果路径映射。它们分别决定响应是否合法，以及如何读取每条 LLM 标准的结论：

```json
[{"criterion_id":"C001","verdict_path":"/criteria/C001/verdict","reason_path":"/criteria/C001/reason","evidence_path":"/criteria/C001/evidence"}]
```

结论使用 `pass`、`fail`、`insufficient_evidence`、`not_applicable`。理由是字符串，依据是字符串数组。未映射的标准不会被推断为通过；程序结果不由模型返回覆盖。

返回 Schema 顶层必须为 object，本地按 Draft 2020-12 校验，禁止外部 Schema 引用。注意：标准里的 JSON Schema 检查原始字段，而这里的 Schema 检查模型响应，两者不同。

## 5. 选择样本、执行和基本预览 {#execution}

“执行与导出”集中展示项目、数据集、字段、标准、评测器和模型信息。先确认保存版本，再在本页勾选样本。

- “试评选中的第 1 条”使用勾选顺序中的第一条，页面显示具体 ID，不会静默改用其他样本。
- “运行所选范围”默认运行勾选记录，支持跨预览页勾选。
- 全量运行必须选择“全部记录”并明确勾选确认。首次真实接口验收只选择一条。

程序串行逐条执行，逐条保存。取消在样本之间生效，正在等待的单次 HTTP 请求不会立即中止。刷新或切换项目不会取消运行。服务重启将未完成记录标记中断，用户决定是否重试。

结果表格显示执行状态、标准结论和理由。展开可看原始记录、依据、请求、原始正文、规范化正文、解析载荷和全部尝试。完整 JSON 代码围栏会在本地剥离，原文仍保留。

| 执行状态 | 含义 |
| --- | --- |
| 调用失败 | HTTP、网络、超时或服务协议异常 |
| JSON 解析失败 | 正文不能作为严格 JSON 解析 |
| Schema 不匹配 | JSON 能解析，但返回结构不合要求 |
| 结果映射失败 | 无法从配置路径读取合法结论、理由或依据 |
| 已完成 | 本次执行链路完成；内容仍可能不通过或依据不足 |

技术失败不是内容不合格。这里不计算总分、总体准确率，也不提供人工复核和回归案例模块。详细分析在导出后进行。

### 重试和复测

“原配置失败重试”只处理未完成记录，在原运行追加 attempt，保持原数据和配置快照。服务重启后，当前公开模型配置指纹必须一致；仅换密钥不改变指纹，模型、地址、参数变化则需要新建复测。

“载入本次运行配置”恢复当时的字段、标准和评测器版本。修改并保存后，在结果表格勾选原运行中的样本，点击“选中样本新建复测”。它创建新运行并关联原运行，不覆盖旧结果。其他数据集或未参加原运行的样本，应新建普通任务。

### 导出

XLSX、JSONL 默认导出全部原始列和全部原始行，保留行序。未选中行标为 not_run，失败行保留错误。额外包含行/运行/尝试 ID、标准结果、理由、依据、解析载荷和配置定位信息。

自定义保留列时，评测字段所属的顶层列固定保留，再加勾选的其他列。选了 `/task/question` 就会整体保留原始 `task` 列，包括同列其他嵌套内容；如需更精细控制，请在导入前调整列结构。

JSONL 使用 `original`、`evaluation` 两个对象，保留数组和对象。XLSX 使用追加的 `eval.*` 列，复杂值保存成 JSON 文本，不执行单元格公式。原始列与追加列冲突、单元格超长等会明确报错，可改用 JSONL。原始模型响应是可选导出项，默认关闭。

导出文件和不含原始业务快照的清单登记在所属运行下。下载不会因为溯源而附带未选择的原始列。

## 6. 项目内历史和版本 {#history}

历史按数据集、字段配置、标准方案、评测器、运行、设计调用分类。可以查看内容、版本、引用、调用详情和操作时间，重新加载已保存对象。

标准和评测器支持两版内容对比。提取调用可“恢复候选为未保存草稿”，只有再次保存才产生标准版本。

单对象归档覆盖其全部版本，默认列表隐藏，勾选“包含已归档对象”可查看及恢复。归档对象恢复后才能用于新执行。项目整体恢复不会改变其子对象单独归档的状态。

单对象永久删除需确认 ID 和范围。标准被评测器引用、评测器被运行引用、运行被后续复测引用、设计调用被标准关联时会返回引用清单并拒绝删除。归档引用同样有效。

允许删除数据集时清理字段配置和上传副本；允许删除运行时清理所属导出文件。整项目删除的规则见第一节。删除出现“暂存文件待清理”时，请检查数据目录的 .deleting 文件夹。

刷新和重启保留服务端保存内容，未保存的草稿不自动保存。浏览器只记住项目及最近选择对象的 ID，不是数据本体。

## 7. 全局模型设置 {#model}

不用打开项目也能进入“模型设置”。所有项目共用八个字段：

| 字段 | 含义 |
| --- | --- |
| api_url | 完整 HTTP(S) Chat Completions 地址，不追加路径 |
| api_key | Bearer 密钥，仅用于后端发送 |
| model | 供应商模型标识 |
| max_tokens | 单次输出上限，正整数 |
| timeout | 网络操作超时秒数，有限正数 |
| stream | 是否按 SSE 接收流式响应 |
| enable_thinking / skip_special_tokens | 布尔值，在 extra_body 对象中发送 |

“保存并生效”写入服务端本地 JSON 并热加载，不发起测试请求。已经提交的任务固定原连接，其他项目后续调用使用新设置。首次需要填写密钥；已配置时留空保留，清除有独立按钮。密钥不回显、不进入数据库和导出。

“测试连接”会发送一次短请求，使用你当前填写的设置，但不会保存。HTTP 和协议成功不代表评测返回结构或判断质量已经通过。确认设置后，仍需点击“保存并生效”才会成为全局配置。

没有配置或配置非法时，项目管理、导入、编辑、静态预览、帮助及纯程序规则仍可用；需要 LLM 的提取、分析和执行会阻止。不自动重试、不降级，不读取其他项目仓库的服务或凭证。

本轮不发送 response_format，结果由 Prompt 和本地校验约束。参数是否兼容供应商仍需按自己的配置单条验收。

## 8. 常见问题 {#faq}

| 问题 | 检查方式 |
| --- | --- |
| 上传后刷新看不到 | 确认打开的是同一个项目，检查历史与归档状态 |
| 不能开始评测 | 字段、标准、评测器是否保存，评测器是否绑定当前标准版本 |
| 模型返回围栏仍报错 | 是否只有一个完整围栏；是否含解释文字、截断内容或非法 JSON |
| 修改标准后还是旧行为 | 重建并保存评测器，再新建复测 |
| 不能删除对象 | 展开引用清单；单对象保护不因归档解除 |
| 全局配置变了，旧任务怎么处理 | 在途任务保持旧连接；旧配置不能复用时用新配置新建复测 |
| 旧版数据在哪里 | v1 使用 workbench_v1.sqlite3，不读取旧 workbench.sqlite3；旧文件未自动删除 |

部署与备份见 [Linux 部署](Linux部署.md)。
