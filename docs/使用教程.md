# 标准库与分组批跑使用教程

本文对应存储修订 4。页面顺序为项目、数据集、标准库、批跑方案、执行与导出、历史记录、模型设置。

## 1. 创建项目和准备数据

数据集、标准库、批跑方案和执行页在没有项目时也可打开。浅灰文字说明待填写内容。可以先写标准或消息草稿，从该页创建项目后再保存。数据、标准、方案和运行都属于当前项目，切换项目不取消后台运行。

“数据集”支持 JSON、JSONL、XLSX，单文件最大 100 MiB。XLSX 可填写工作表名称和表头行，留空使用第一张工作表。原始记录按源顺序展示，支持 10／20／50 条分页。点击单元格打开完整内容，可在弹窗内复制。评测字段在执行页勾选。

## 2. 设计一条独立标准

标准库每次编辑一条标准：

| 填写处 | 内容 |
| --- | --- |
| 标准名称 | 清楚且稳定的名字；同一批跑方案中名称不能重复 |
| 评测方式 | LLM 判断、程序非空、程序 JSON Schema |
| 标准描述 | 判断依据、适用范围、边界和信息不足时如何处理 |
| 输出规则模板 | LLM 专用，定义这条标准的返回字段、类型和选项 |
| 作用字段／规则 Schema | 程序规则专用，执行时须在本组勾选该字段 |

例：名称“回答质量”，描述“按事实正确性与材料完整性分为 A/B/C；理由指出具体依据”，模板：

```text
{
  "等级": choice:["A", "B", "C"],
  "理由": value:string
}
```

模板编辑后自动编译预览，不调用模型。“保存新版本”追加当前标准版本，“另存为”创建新的独立标准。历史版本下拉可加载旧版本。旧版本修改后保存仍追加新版本；已有批跑方案保持原引用。

“管理”可看引用、归档、恢复或删除。归档标准在日常选择中隐藏；引用它的方案执行前需恢复或替换。删除会检查所有保留方案、运行和测试的引用，拒绝时列出引用对象。

## 3. 保存分组批跑方案

新建方案，从标准库加入标准，默认每条各自成组。引用版本下拉可以选择具体版本；标准有新版本时可点“更新引用版本”查看前后变化，采用后需保存方案。

组名按顺序生成。可调整组顺序和组内标准顺序，也可移动标准、合并或拆开组。每条标准在方案中只出现一次，所选标准名称必须唯一。各组不能读取其他组输出。

| 五条标准的分组 | 每条数据初始模型请求数 |
| --- | ---: |
| `[1,3] [2] [4] [5]` | 4 |
| `[1] [2] [3] [4] [5]` | 5 |
| `[1,2,3,5] [4]` | 2 |

在共用 System／User 消息中至少包含 `{{criteria}}`、`{{fields}}`，以及 `{{output_instructions}}` 或 `{{response_schema}}` 之一。变量按每组独立渲染。只读结构预览来自各组引用的标准版本，不手写整体 Schema 或结果映射。

“预览请求”可对草稿选数据集、样本和字段，查看按组组装的 System、User、输出结构和完整请求。预览只组装消息，无模型调用，也不改变执行页的字段选择。保存方案后会显示当前版本。

## 4. 勾选字段、试跑与执行

“执行与导出”选择数据集和已保存方案，勾选共用评测字段。某组需要不同输入时，展开“按组调整字段”单独勾选。切换数据集后重新选择字段。程序规则的作用字段需要被该组勾选。提交时，实际勾选的字段会保存在运行快照中。

点击预览表中的单元格可查看完整值。“试跑选中第 1 条”对第一条选中记录执行全部组并保存试跑结果。也可以直接正式批跑。

正式批跑选择所选记录或整个数据集。所有组共用提交时的全局模型及并发上限；五个组不会各分配一套并发。不同运行 FIFO 排队。纯程序组无需模型；混合组先检查程序规则，业务不通过不阻止 LLM。

## 5. 失败、重试与取消

技术失败包括调用、JSON 解析和结构校验失败；低分或差等级是有效业务结果，不重试。组内任一标准返回错误使整组技术失败，完整响应保留；同一行其他成功组不受影响。

首轮所有组任务结束后，仅失败且有额度的组进入自动重试轮次并排到 FIFO 队尾。每条数据的每组最多追加 3 次；初次加自动重试最多 4 次。预算持久化，人工重试和服务重启不清零。额度用尽等待人工；“原配置失败重试”只重试失败／未完成组，永远跳过成功组。新建复测或按原配置新建运行获得新的预算。

“取消任务”停止新派发，等待所有在途结果保存；未派发组保持未执行。取消、重启中断、调度和保存异常不自动续跑。重启后未完成任务标记中断，需明确人工重试。

结果同时显示完整成功数据条数和组任务成功／异常／执行中／未执行数量，重试次数不加入初始任务总数。正在重试的旧结果标记“上次尝试”，不会当成本轮成功结果。

## 6. 结果、历史与导出

执行结果和历史详情的「统计」页签按组、标准和字段显示整次运行的结果。单选和多选显示各候选项的数量及占比，数值显示平均、最低、最高，自由文本显示填写和空白数量。分母为对应字段的有效结果数；失败、未执行、执行中和中断按组单独计数。多选可同时命中多个标签。运行期间可手动刷新统计。

结果表一条原始记录一行，表头按执行组／标准／字段排列。失败或未执行组输出留空，显示其真实状态；成功组保留输出。程序结果独立展示。可按失败组及错误阶段筛选整次运行，分页保持源行顺序。

行详情可看原始数据、完整有效 JSON、各组字段、标准版本和自动／人工尝试，包括实际请求、原始响应和耗时。历史页以时间、类型、情况、数据集简短展示；详情在暗色模糊背景弹窗中查看，不改变编辑状态。

“载入编辑”恢复方案与组字段选择为草稿。保存后可用当前模型复测，样本限于原运行。想选择其他样本时，点击执行页的“退出复测”，当前配置和勾选记录会保留。“按原配置新建运行”固定原快照和公开模型参数。“原配置失败重试”在原运行增加尝试，模型公开参数变化时需恢复或另建复测；仅更换密钥允许重试。

XLSX 保留原始列、`result/标准名/字段名`、组状态／错误和完整 JSON，名称路径段按 JSON Pointer 转义；数值保持数值，多选写 JSON 文本。JSONL 保留嵌套输出、原始数据与组执行信息。可选导出全部尝试的请求和原始响应。两种格式覆盖整个源数据集，保留未选中、取消未执行及失败行，不丢行；列冲突会报错。

## 7. 模型和部署

模型设置先保存命名配置，再启用。API Key 留空保留同一配置原密钥，复制为新配置需重新填写。并发上限 1～32 控制整个批跑内组任务数量，不是请求速率。连接测试不保存、不启用、不验证业务质量。

密钥仅在本地连接文件及运行内存中使用，不进入业务快照或导出。部署修订 4 需停服、备份并自行清空旧业务目录，详见 [部署说明](Linux部署.md)。
