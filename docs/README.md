## 迭代约定

- 产品范围与验收口径、技术协议、设计决策等文档继续放入 `docs/`，并在此补充索引。
- 变更时明确区分建议、已确认决策和已实现行为；涉及取舍时记录原因及影响。
- 更新现有文档并通过 Git 查看历史，避免复制出多个含义不清的“最终版”。
- 设计变更与相关实现保持同步，不能将计划中的能力写成已经完成。
- 测试数据及示例生成 Prompt 保留在仓库外的 `../../testdata/`；文档可以引用，但不将其复制进本目录。

## 当前进展

2026-10-27：完成方案评审和旧链路删除后，在同一仓库实现 v0。支持 JSONL、JSON、XLSX，串通标准设计、试评/批跑、人工复核、回归案例与导出。当前前端为原生 HTML/CSS/JavaScript，由 FastAPI 提供页面与接口。已补充服务端 JSON 模型配置、各环节独立模拟/真实模式、历史归档恢复及引用保护、设计调用持久化和运行溯源。自动验收仅使用模拟网络；真实供应商兼容性和评测准确性仍待验证。原始交接文档保留原文，当前行为以 v0 实现记录为准。

同日部署调整：moto 仅为本地调试环境，部署支持其它 Python 3.10+ 环境。按简化部署要求，前端已改为无构建源码，删除 Node.js 工具链、专用打包脚本及旧发布产物。直接复制项目后由 Python 启动，支持 host/data-dir 参数，Python 依赖统一为一份 requirements.txt。
