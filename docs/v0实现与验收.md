# v0 实现与验收

> 历史记录：不适用于当前 v1。当前操作与验收见 [v1 实施与验收](v1实施与验收.md) 和 [使用教程](使用教程.md)。

日期：2026-10-27。本文描述当前实现，优先于原交接方案中尚未收敛的实现建议。v0 只评已有输出，导入支持 JSONL、JSON、XLSX，CSV 不在范围内。

## 当前能力

1. 导入文件、预览记录、选择 XLSX 工作表及表头；映射多个输入、输出和可选参考字段。
2. 手动配置独立标准；可选读取生成任务 Prompt，使用模拟或真实候选提取及依据分析，再人工编辑确认。
3. 用模板构建 Judge Prompt，编辑返回 JSON Schema、结果路径映射及模拟响应；真实连接集中在服务端 JSON。
4. 预览单条请求；单条试评或明确选择样本串行批跑，查看进度、取消及原配置失败重试。
5. 查看每次 attempt 的请求、模型原始响应、解析状态及标准判定；追加人工复核，人工独立确认后保存回归案例。
6. 选择结果载荷字段追加导出 XLSX；使用新评测器版本新建复测，或复测同一标准方案下的人工案例。

页面分为数据管理、评测标准、评测器、执行任务、结果与复核、历史管理。保存的对象及运行可在刷新、重启后重新打开；未保存草稿不自动保存。

## 模拟与程序规则

- 标准提取、依据分析、评测执行独立使用 execution_mode=mock|real，省略时默认模拟。统一模型适配层使用 httpx，支持普通 JSON 和 SSE；自动测试只使用 MockTransport，不发送真实请求。
- 真实连接读取 config/llm_config.local.json，八字段协议与 project1 一致，但不复制其凭证。地址为完整接口 URL；请求包含 Bearer 鉴权及 extra_body，不自动追加路径或 response_format。配置启动时读取校验，缺失或非法不影响模拟，不自动探测、重试或降级。
- 页面只读展示公开参数、地址哈希和配置指纹。密钥不进入持久记录。实际耗时和供应商用量保留，无用量则为空，不估算费用。旧评测器预设只作为历史信息，新真实请求采用服务端 JSON。
- 请求按 OpenAI Chat Completions 风格组织，调用用途区分 extract、evidence_analysis、judge；原始响应保留 chat completion 信封。
- 候选提取默认返回通用模拟条目；真实模式返回可编辑候选。依据分析保留程序的角色存在性检查，模拟或真实模型仅提供建议，不覆盖确定缺失；字段存在不等于依据充分。
- Judge 默认模拟“依据不足”，可配置模拟故障和响应；真实内容进入同一 JSON 解析、Schema 校验和结果投影流程。
- 非空、待评测输出 JSON Schema 是真正执行的内置规则，不调用模拟模型。没有给定作用字段时使用第一个映射输出。
- 程序规则的结论保存在统一标准结果中；模型原始载荷只表达 LLM 步骤的结果，不能用载荷覆盖规则结果。
- 缺少必要依据的标准输出 insufficient_evidence；整行映射输出均不存在或为 null 时跳过。已有但为空的输出可由非空规则判 fail。

## 数据与版本协议

后端类型在 `backend/models.py`，接口文档可在运行后的 `/docs` 和 `/openapi.json` 查看。基础接口为 `/api/v1`，涵盖数据导入与预览、映射、标准、提取、依据分析、评测器、请求预览、运行、人工复核、回归案例和导出。

- 字段与结果路径采用 JSON Pointer，例如 `/task_input/question`、`/criteria/C001/verdict`；字段名中的 `~`、`/` 分别转义为 `~0`、`~1`。
- JSON 支持单对象或对象数组；JSONL 每个非空行必须是对象。保留嵌套对象和数组，数组不自动拆分成新样本。
- XLSX 保留单元格值，日期转为 ISO 字符串；公式按文本保留，不执行公式。单元格内的 JSON 文本不自动猜测为对象。表头不能为空或重复；默认读取第一行，可改。
- 每个数据集分配稳定内部行 ID，并保留源行号、原始记录、文件副本与 SHA256。外部业务 ID 无须唯一。
- 映射、标准、评测器采用追加版本；运行保存当时的数据及全部配置快照。复测新建运行，失败重试在原运行追加 attempt，不改变原配置。
- 运行固定执行模式和公开模型配置。重启后配置指纹不一致时拒绝原配置重试，应新建复测；仅轮换密钥不影响指纹。旧模拟记录缺少新增字段时按原模拟语义读取，不覆盖原快照。
- 自定义响应 Schema 顶层必须是 object，本地按 JSON Schema Draft 2020-12 校验。拒绝外部 `$ref` / `$dynamicRef`，不下载远端 Schema。
- 结果投影将指定 JSON Pointer 关联标准 ID、判定、理由及字符串数组依据。未配置投影的标准保留为未映射，不推断通过率。
- 人工复核独立保存，并关联当时的 attempt。模拟来源需明确人工确认后才可保存案例；案例不自动充当总体准确率证据。

## 执行、统计与导出

使用进程内单工作线程和 SQLite，须以单进程启动。运行选择 selected 或 all，不默认全量；取消在记录之间生效。服务启动时将遗留排队/运行中任务标为 interrupted，由用户重试。

提取和分析调用先保存为 design_call，记录模式、请求、响应、解析状态、时间、公开配置和输入快照，失败也保留。未完成设计调用重启后标记中断。标准保存关联 design_call_ids；恢复提取结果仅生成草稿。分析调用保存当时标准内容快照，不建立反向的标准对象删除依赖，以免“标准关联分析调用、分析调用关联同一标准”形成不可解除的环；数据集和映射仍是受保护的实时引用。

工程状态包括 pending、running、completed、call_failed、parse_failed、schema_failed、projection_failed、skipped 等；标准结论为 pass、fail、insufficient_evidence、not_applicable。统计只计最新 attempt 中明确的标准结论，不将技术异常、未映射结果或人工修订混成模型失败，不生成隐含总分。

导出保留全部原记录及顺序，追加 `eval.*` 列；未选中行显示 not_run。载荷字段列用 `eval.payload` 加 JSON Pointer 命名；数组和对象以 JSON 文本写入，文本不会作为公式执行。字段冲突、单元格超长或超出 XLSX 容量时明确报错，不覆盖或截断。导出旁保存包含完整运行快照的 JSON 清单。

导出文件名和 eval.is_mock 区分模拟/真实；每项标准仍保留程序规则、依据检查或 LLM 来源，不将真实模式等同于每条标准都调用了模型。

## 历史与接口增量

SQLite 增量增加 lifecycle 和 audit 表，旧对象默认未归档；配置版本和旧运行不重写。归档整个对象及全部版本，默认列表隐藏，可查看并恢复。归档对象不能用于新操作，旧运行快照保持不变。保存和生命周期操作记录动作、时间、对象 ID，无身份系统。

删除在共享锁内检查所有版本、保留运行（包括归档记录）的引用；有引用返回 409 和清单，不级联删除。数据集拥有映射版本及导入副本，运行拥有导出文件；案例、后续运行和关联标准版本会保护其上游。运行中的任务和设计调用不可归档或删除。文件路径限定在当前数据目录，拒绝符号链接及重解析点，先暂存再提交删除；异常回滚，残余暂存文件会明确提示。

| 接口 | 内容 |
| --- | --- |
| GET /api/v1/llm/status | 脱敏配置状态，无读取或修改密钥接口 |
| GET /api/v1/history?kind=&include_archived= | 分类历史、引用和可操作状态 |
| GET /api/v1/history/{kind}/{id} | 对象、版本、引用和审计事件 |
| POST /api/v1/history/{kind}/{id}/archive 或 restore | 整体归档 / 恢复 |
| DELETE /api/v1/history/{kind}/{id} | confirm_id 必须与路径 ID 一致，受引用保护 |
| GET /api/v1/history/events?object_id= | 保存、创建运行及生命周期事件 |
| GET /api/v1/entities/{id}/compare?left=&right= | 标准 / 评测器两版内容差异 |

原提取、分析、预览、创建运行、复测接口支持 execution_mode；旧调用省略时仍模拟。原配置重试保持原模式，不接受模式覆盖。

## 存储位置与限制

默认在仓库外 `../review_workflow_data/` 保存 SQLite、导入副本和导出产物。通过启动参数或进程环境变量 EVAL_DATA_DIR 指定数据目录；程序不自动读取 `.env`。外部 `../testdata/` 不被程序自动加载。

部署使用任意名称的 Python 3.10+ 环境，moto 只约束当前机器调试。前端为原生 HTML/CSS/JavaScript，直接随源码提供，开发与部署均不需要 Node.js 或前端构建。启动入口支持 `--host`、`--port`、`--data-dir`，命令行数据目录优先于环境变量。直接复制源码的步骤见 [Linux 部署](Linux部署.md)。

v0 文件上限 25 MB，前端每页预览 50 条；选择记录可跨页保留。暂不提供筛选器、随机抽样、用户权限、外部队列、多进程并发或完整 Excel 样式/公式的无损往返。运行与快照存为 SQLite JSON，适合本地小规模验证，未做大数据性能验收。

## 验收记录

验收围绕一条合成业务记录，复用该记录检查格式、版本及故障分支，不读取外部业务数据，不做全量评测，不发送真实模型请求。

- Python 验证：保留 11 项原评测链路测试和 3 项源码部署测试，新增配置、普通响应、SSE、超时/HTTP/解析/Schema/投影异常、三环节模式、设计调用持久化、指纹重试、归档恢复、引用保护、所属文件清理、旧库副本迁移等测试。所有网络均用模拟传输，业务数据只复用一条合成记录。
- 前端不再进行构建或 TypeScript 检查；原 React 测试随工具链删除。当前验证原生脚本语法、控制器流程与 Python 静态资源服务，真实浏览器视觉验收仍单独说明。
- 当前没有连接可用的浏览器，尚未进行真实浏览器交互和视觉验收。交付后可按 README 的单条体验步骤检查页面。

本轮完善验收：moto 环境下 35 项 Python 测试通过。原生前端控制器使用同一条合成记录串通六个页面、导入、映射、设计调用、评测器保存、预览、试评、复核、候选恢复及历史归档/恢复/加载；控制器验证使用临时工具，不作为部署依赖。没有访问真实模型，也没有读取外部测试资料。真实接口及浏览器视觉验收仍待用户环境验证。

通过以上检查仅证明工程链路和状态处理，不证明自动提取质量、Judge 准确性、实际供应商兼容性或多条数据下的运行性能。
