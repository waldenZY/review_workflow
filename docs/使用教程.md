# Eval Studio v1.1 使用教程

本工具评测你已经准备好的内容，不负责生成待评测数据。分析工作在导出后进行，这里提供配置、执行、基本预览和导出。

[TOC]

## 1. 创建和打开项目 {#projects}

先在“项目”页点击“新建项目”，填写名称和可选说明，保存后点击“打开”。首次不会自动创建默认项目。

v1.1 使用数据根目录下独立的 `v1_1/` 存储，从空项目开始，不读取或删除旧版业务记录。

一个项目可以包含多个数据集、标准方案、评测器和运行。例如同一工作主题下的不同评测方案可以都放在这个项目，依靠名称、ID、时间和版本区分。项目之间的业务记录不能相互引用或移动；模型连接全局共用。

首页连接成功后即可操作，项目列表和模型配置分别显示加载或错误，各自返回后立即显示，失败可分别重试；不会等待上次运行的全部材料恢复；进入数据、标准或运行模块时才加载相应内容。顶部项目选择器可以切换。未保存的字段、标准或评测器修改会提示是否放弃；切换后恢复该项目最近选择的保存对象。正在后台执行的任务不因切换而取消，返回原项目仍可查看。

项目列表可查找名称或说明、修改项目名称和说明。“更多操作”中提供归档和永久删除。归档表示从日常列表隐藏且只读，数据仍保留、可恢复；删除则永久移除。归档后默认隐藏，勾选“包含已归档项目”可查看和恢复。归档项目仅供查看历史和导出，恢复后才能编辑或执行。

永久删除先展示对象、版本和文件数量，再要求输入项目名称。它会整体清理项目业务记录与所属文件。项目内部的引用不会阻止整包删除，但未结束的运行或设计调用会阻止删除及归档。外部原始资料、其他项目、全局模型配置和旧数据库不在删除范围内。

## 2. 导入数据和选择评测字段 {#data}

打开项目后，在“数据与字段”选择文件，确认导入。支持 UTF-8 JSONL、JSON、XLSX，单文件最大 100 MB（100 × 1024 × 1024 字节），不支持 CSV。文件选择、XLSX 工作表检查和正式导入使用相同上限。导入期间仍完整解析文件，内存占用可能高于文件大小；此上限不是已验证的容量或耗时保证。

| 格式 | 内容要求 |
| --- | --- |
| JSON | 单个对象或对象数组，每个对象是一条记录 |
| JSONL | 每个非空行是一个 JSON 对象 |
| XLSX | 选择工作表和表头行；表头不能为空或重复 |

工作台保存导入副本、原始记录、文件 SHA256、源行号和稳定内部行 ID。数据集记录不会因刷新或重启消失。同名上传通过时间和 ID 区分，不覆盖已有数据。

嵌套对象和数组保留原结构，数组不自动拆成新记录。XLSX 中的 JSON 文本不自动猜测成对象，公式按文本保存，不执行公式。

数据页、样本页和结果页底部统一提供分页：记录范围、每页 10／20／50 条、上一页、页码下拉框和下一页。页码框收起时显示当前页，展开后直接选择目标页；改变每页数量回到第 1 页，跨页勾选保留。加载失败保留上一次成功显示的页面。

数据表格上下的滑块是联动的横向滚动条，用于查看左右列，不是分页。无横向溢出时不显示。预览默认单行截断；点击单元格查看完整文本、对象或数组，按关闭或 Escape 返回。

“参与评测的字段”决定哪些材料进入 Judge 和依据分析。全部标准共同使用这些字段，不需要区分任务输入、已有输出或参考角色。

字段路径是 JSON Pointer，不是电脑文件路径：

```json
{"record_id":"A01","task":{"question":"问题"},"answer":"已有回答","reference":"核对资料","internal_note":"仅供内部分析"}
```

| 路径 | 读取位置 |
| --- | --- |
| `/task/question` | task 对象里的 question |
| `/answer` | 已有回答 |
| `/reference` | 核对资料 |

字段名中的 `~`、`/` 在路径中分别写为 `~0`、`~1`。选择父对象时，其子内容整体参与评测。勾选后数据预览对应顶层列变浅色，将鼠标停在表头可查看实际选择路径；嵌套子路径的列高亮不表示其他子内容也会发送。

勾选需要的字段并“保存字段配置”，产生配置版本。未选中的原始列不会自动发送给模型，但默认仍会随结果导出。修改勾选后必须保存，旧运行的字段快照不受影响。

同一数据集可以保存多套命名字段方案，字段方案不固定绑定某个标准。点击“新建字段配置”建立草稿，或编辑后“另存为新方案”；编辑已有方案后“保存新版本”保留旧版本。下拉框用于快速切换，旁边“管理”只列出当前数据集的字段方案，可查看版本、载入、归档、恢复及删除。数据集也在本页独立管理。

## 3. 标准与输出模板 {#standards}

每条启用的 LLM 标准分别填写名称、描述和输出规则模板。名称在方案内唯一；描述写清判断条件、候选项含义、优先级和依据不足时的处理。每个模板只填写本标准的字段，平台自动包裹标准名称并组合成一个 JSON。

```text
{
  "等级": choice:["A", "B", "C", "无法判断"],
  "说明": value:string
}
```

支持 `choice:[...]`、`multichoice:[...]`、`value:string` 和 `value:number`。全部字段必填，多选可为空但不能重复，不支持嵌套、可选或空值；数值范围和业务判断不由此简写自动验证。完整写法和交付示例见仓库 `docs/评测标准与输出模板规范.md`。

模板输入后约 500ms 自动检查，显示字段及行列错误和本标准结构示例，不保存、不请求模型。启用 LLM 标准缺少合法模板不能保存；关闭的标准可保留未完成模板，不参与输出。提取候选只产生名称和描述，需手工补全模板。程序非空和程序 JSON Schema 不需要输出模板，不调用模型。

保存新版本延续原标准方案，另存为创建独立方案。名称、描述、模板和启用状态随版本保存；历史运行使用原快照。多个标准可以使用同名输出字段，标准分组将它们隔离。所有标准共用选定字段方案，不强制区分输入、输出、参考角色。

实际判定要求应放入标准描述或消息，设计备注不发送给模型。原生成任务 Prompt 仅供用户主动提取标准，不自动追加到评测请求。材料中的指令作为数据处理。

“管理”提供方案内容、版本、归档、恢复、删除和引用查看。标准页“设计调用记录”管理提取／依据分析的原始调用；成功的提取可恢复为草稿。依据分析只针对当前样本给建议，不形成执行门禁。

## 4. 评测器消息与只读返回结构 {#evaluator}

选择或保存标准后自动准备匹配的评测器，不调用模型、不自动保存。评测器编辑名称、System 和 User 消息；整体返回 Schema、字段顺序和结构示例由绑定标准版本自动派生，只读查看，不需填写结果映射或手工 JSON 示例。

| 消息变量 | 内容 |
| --- | --- |
| `{{criteria}}` | 全部启用 LLM 标准的名称和描述 |
| `{{fields}}` | 当前样本共同评测字段的内容 |
| `{{output_instructions}}` | 由各标准模板生成的分组结构要求和示例 |
| `{{response_schema}}` | 同一份整体 JSON Schema |

消息必须包含 `{{criteria}}`、`{{fields}}`，返回约束至少包含后两者之一。模板外没有隐藏追加。消息、样本和字段变化会自动刷新预览；预览不保存、不发送模型请求，未配置模型也可查看。

标准改名、启停或修改模板后自动更新组合结构，保留已编写的消息文本；检查后仍需保存评测器版本才能执行。跨方案复用仅复用消息，输出结构采用目标标准方案。另存为创建独立评测器；高级区可以查看派生 Schema、恢复默认消息和查看版本差异。

不同标准格式错误不会触发拆分调用。一条数据记录只请求一次并返回全部启用 LLM 标准的分组；只有所有分组合法才算该行执行成功。

## 5. 选择样本、执行和基本预览 {#execution}

“执行与导出”集中展示项目、数据集、字段、标准、评测器和模型信息。先确认保存版本，再在本页勾选样本。样本表按共同评测字段逐列展示，源行与复选框单独成列；点击内容查看完整值不会改变勾选。上下横向滑块联动，底部页码框直接跳页。

- “试评选中的第 1 条”使用勾选顺序中的第一条，页面显示具体 ID，不会静默改用其他样本。
- “运行所选范围”默认运行勾选记录，支持跨预览页勾选。
- 全量运行必须选择“全部记录”并明确勾选确认。首次真实接口验收只选择一条。

不同批跑按提交顺序排队。同一批跑内部，按照提交时模型配置的“批跑并发数”同时处理记录，完成一条就保存并补充下一条；纯程序规则仍串行。每条记录的 LLM 标准共用一次调用，结果完成顺序可以不同，但按行 ID 保存，预览和导出保持原始行序。

进度显示整体及本轮已处理／成功／异常数量，并区分执行中（请求及解析）、等待保存、待执行。固定并发是上限，不代表始终有同样数量的网络请求；执行中不是实时 HTTP 连接数。已处理包含技术失败，不代表内容通过。结束或取消后的剩余记录显示为未执行。

点击取消先显示正在提交，后端确认后显示“正在取消”，停止派发新记录，等待已派发记录结束并保存后再结束任务；已有结果和错误不会删除，变为“已取消”后可以导出。在途 HTTP 不强制中止，未派发记录仍可明确重试。刷新或切换项目不会取消运行。关闭后迟到响应不再写入已关闭的数据库，重启将未完成任务及记录标记中断，用户决定是否重试。

结果表格按 10/20/50 条分页，将本次固定的评测字段材料与执行状态、自定义输出字段放在同一行。材料可点击查看完整值，表格上下可横向滚动，修改当前字段草稿不影响历史材料。

“结果范围”可选全部、执行异常、未执行；执行异常可进一步按调用、JSON 解析、Schema 或调度阶段筛选。筛选覆盖整次运行，不只当前页；业务低分或差等级不是技术异常，也不改变导出范围。

进度每 2 秒独立读取，不等待结果页完成，并只更新运行状态区，不重建整个页面。结果页一次只读一个请求，重复刷新会合并，页码、筛选、勾选及展开的详情保留。普通读取 15 秒超时，轮询失败后按 2／4／8／15 秒退避恢复；页面保留上次成功数据并显示更新时间。结果页失败可以点“重试结果页”，失败的读取不会重复提交模型请求。上传、导出和设计调用不采用普通读取的短超时。

“记录与历次尝试”点击加载后先展示各次状态、错误阶段和摘要、轮次及时间，耗时、请求、响应和解析过程分别折叠，正文首次展开时格式化并复用。旧尝试没有阶段耗时或轮次时显示未记录。配置快照及执行轮次可另行加载。

任务结束时会再次读取当前结果页。若最后一次查询失败，显示“任务已结束，最终结果页尚未更新”，可手动重试；这不代表需要重新执行评测。离开运行页时不继续读取结果表，返回后恢复必要的收尾查询。

阶段数量若显示“更新中”，表示保存／补位恰好与查询交错，无法给出同一时间点的确定数字，不等于 0；整体进度仍可查看。

详情新增 attempt 后会提示“当前记录已有更新”，由你手动刷新。缓存超过最近 10 条或估算 10MiB 时回收已关闭的详情，打开的内容不强制关闭；关闭后可能需要重新加载。材料仍以完整字段值随当前页加载，表格截断仅影响显示。

评测响应只允许纯 JSON 对象，可以有 JSON 首尾空白。拒绝代码围栏、BOM、外围解释、重复键及非有限数值，不从解释文字中猜取 JSON，不自动请求模型修复。任意标准分组不符合模板，整行记为技术异常，原响应保留。

| 执行状态 | 含义 |
| --- | --- |
| 调用失败 | HTTP、网络、超时或服务协议异常 |
| JSON 解析失败 | 原文不是纯 JSON 对象，存在代码围栏、解释、重复键、非有限数值或语法错误 |
| Schema 不匹配 | JSON 能解析，但返回结构不合要求 |
| 已完成 | 本次执行链路完成；内容仍可能不通过或依据不足 |

技术失败不是内容不合格。这里不计算总分、总体准确率，也不提供人工复核和回归案例模块。详细分析在导出后进行。

### 重试和复测

“原配置失败重试”只处理未完成记录，在原运行建立新轮次并追加 attempt，保持原数据和配置快照。页面同时显示整体进度及本轮数量／进度；当前重试未返回时，之前的错误和结论明确标为“上次尝试”。技术执行成功但内容不通过的行不会自动重试。重试使用原运行绑定的命名模型配置，无需把全局选择切回。绑定配置的公开指纹必须与原运行一致；仅换密钥不改变指纹，模型、地址、参数变化则需恢复参数或新建复测。配置已删除或密钥缺失时不能原配置重试。重试固定使用原运行的并发数，仅修改模型配置里的并发数不改变模型指纹，也不会改变原配置重试的并发。

“载入本次运行配置”与历史详情中的“载入配置并编辑”将当时的字段、标准和评测器恢复为新方案草稿，并选中原样本，进入数据与字段页。有未保存草稿时先确认替换；不会自动保存或执行，也不会切换全局模型。依次保存字段、标准和评测器，再进入执行页运行。标准保存后保留原消息，返回结构由当前每条标准模板生成；原来的自定义结果映射已移除。数据集归档时需先恢复。历史原配置和结果不变。

### 导出

XLSX、JSONL 默认导出全部原始列和全部原始行，保留行序。未选中行标为 not_run，失败行保留错误。额外包含行/运行/尝试 ID、标准结果、理由、依据、解析载荷和配置定位信息，以及 `execution_config.batch_concurrency` 中的本次并发数。

自定义保留列时，评测字段所属的顶层列固定保留，再加勾选的其他列。选了 `/task/question` 就会整体保留原始 `task` 列，包括同列其他嵌套内容；如需更精细控制，请在导入前调整列结构。

JSONL 使用 `original`、`evaluation` 两个对象，保留数组和对象。XLSX 使用追加的 `eval.*` 列，复杂值保存成 JSON 文本，不执行单元格公式。原始列与追加列冲突、单元格超长等会明确报错，可改用 JSONL。原始模型响应是可选导出项，默认关闭。

导出文件和不含原始业务快照的清单登记在所属运行下。下载不会因为溯源而附带未选择的原始列。

## 6. 历史运行与对象管理 {#history}

历史页只列评测运行，显示时间、数据集、状态、成功／异常／未执行数量。支持状态、数据集筛选和分页，也可包含归档运行。单条试评同样是运行，不会被隐藏。原配置失败重试仍属于同一运行的不同轮次；新建复测和按原配置新建运行各自形成独立记录。

“详情”打开居中弹窗，背景变暗并模糊。结果、本次配置、执行记录分开查看；结果分页，支持集中筛选异常，原始数据及历次请求响应按条读取。快照包括字段、完整标准、消息模板、返回结构、模型公开参数与并发数。查看、翻页、导出或关闭不切换当前编辑页的配置。运行中的详情可手动刷新。

运行详情提供三种复用方式：原配置失败重试只处理技术失败及未执行记录，追加到原运行；按原配置新建运行默认使用原样本，也可在结果表跨页勾选后选择“勾选的若干条”，沿用原业务配置、原模型公开参数及原并发数，创建关联原运行的新记录；载入配置并编辑恢复为新方案草稿，后续执行使用当前全局模型。原模型配置删除或公开参数变化会阻止原配置重试和新建，只有更换密钥不受影响；归档的业务对象需先恢复。详情可导出完整结果，默认包含全部原始列且不含原始模型响应；自定义导出仍在执行页。

数据集、字段方案、标准、评测器在所属页面的“管理”中查看内容、版本及引用，载入编辑、归档、恢复或删除，下拉框继续用于快速切换。标准和评测器支持两版内容对比。保存新版本延续同一方案；另存为新方案立即保存为独立对象。评测器管理还可将所选版本的消息复用为当前标准的新草稿，输出结构由目标标准版本生成。普通切换评测器会同时切换其绑定标准。

归档只限制该对象，不级联关联对象，不影响历史查看和导出；管理窗口包含归档对象。单对象归档覆盖全部版本，恢复后才能编辑执行，项目整体恢复不改变子对象单独归档状态。

单对象永久删除先确认范围，接口继续校验对象 ID。标准被评测器引用、评测器被运行引用、运行被后续复测引用、设计调用被标准关联时会返回引用清单并拒绝删除。管理窗口对已知引用禁用删除，可在详情查看引用清单；归档引用同样有效。

允许删除数据集时清理字段配置和上传副本；允许删除运行时清理所属导出文件。整项目删除的规则见第一节。删除出现“暂存文件待清理”时，请检查数据目录的 .deleting 文件夹。

当前存储修订号为 3，不支持旧数据迁移。部署前停服、备份并由部署人员清空旧业务目录；旧库会拒绝启动，程序不自动删除。

刷新和重启保留服务端保存内容，未保存的草稿不自动保存。浏览器只记住项目及最近选择对象的 ID，不是数据本体。

## 7. 全局模型设置 {#model}

不用打开项目也能进入“模型设置”。可以保存多个唯一命名的连接，其中一份作为全局当前配置。每份都有以下八个字段：

| 字段 | 含义 |
| --- | --- |
| api_url | 完整 HTTP(S) Chat Completions 地址，不追加路径 |
| api_key | Bearer 密钥，仅用于后端发送 |
| model | 供应商模型标识 |
| max_tokens | 单次输出上限，正整数 |
| timeout | 网络操作超时秒数，有限正数 |
| stream | 是否按 SSE 接收流式响应 |
| enable_thinking / skip_special_tokens | 布尔值，在 extra_body 对象中发送 |

### 批跑执行设置

在模型参数框内填写“批跑并发数”，范围 1–32，默认 1。它随命名配置保存，修改当前配置后只影响之后提交的运行，已提交运行保持原值。

例如设置为 3，一次批跑最多同时处理三条记录，结束一条后补下一条。它不是每秒请求数，也不是供应商账户的全局上限；标准提取、依据分析、连接测试不使用此设置。不同批跑仍排队，纯程序规则固定串行。试评只有一条时仍只调用一次，不会重复样本。

并发提高后仍可能遇到供应商限流，工作台会保留技术失败与原始响应，不自动重试、不降低并发。你可以按需调整配置后新建复测，或按原设置明确重试失败记录。

文件里执行设置存放在每个配置的 `execution` 对象，和八字段 `config` 平级，不作为供应商 HTTP 参数发送。缺少该字段的现有配置在内存按 1 处理，下次配置写入时补齐，不迁移业务数据。

操作步骤：

1. 点击“新建配置”，填写名称、地址、密钥、调用参数及并发数，点击“保存修改”。保存不会自动启用。
2. 点击“使用所选配置”，所有项目之后提交的模型调用使用这份配置，顶部始终显示当前名称。
3. 顶部下拉框选择配置只加载参数，不切换全局使用对象。编辑已有配置时，密钥留空保留；更多操作里的“另存为新配置”会清空密钥，需显式填写后保存。
4. 修改当前正在使用的配置并保存，会更新后续调用的参数；已经提交的任务仍保持原连接。
5. 删除、另存为、清除密钥和重新读取放在“更多操作”。删除当前配置会取消全局选择，不自动切换到其他配置；清除密钥不影响其他配置。

所有命名配置存于服务端 `config/llm_config.local.json`，页面保存原子写入并热加载，手动改文件需重启。密钥不回显、不进入业务数据库和导出。本项目原八字段文件只在内存识别为“原有配置”，首次配置写入时转换，不会读取其他仓库。

“测试连通性”会发送一次短请求，使用尚未保存的表单；编辑已有配置可沿用该配置的密钥，新建配置必须填写。测试不保存、不启用。HTTP 和协议成功不代表评测返回结构或判断质量通过。保存、启动和刷新不会自动测试连接。

没有配置或配置非法时，项目管理、导入、编辑、静态预览、帮助及纯程序规则仍可用；需要 LLM 的提取、分析和执行会阻止。不自动重试、不降级，不读取其他项目仓库的服务或凭证。

本轮不发送 response_format，结果由 Prompt 和本地校验约束。参数是否兼容供应商仍需按自己的配置单条验收。

## 8. 常见问题 {#faq}

| 问题 | 检查方式 |
| --- | --- |
| 上传后刷新看不到 | 确认打开的是同一个项目，检查历史与归档状态 |
| 不能开始评测 | 字段、标准、评测器是否保存，评测器是否绑定当前标准版本 |
| 模型返回围栏报错 | 评测链路要求纯 JSON 对象，围栏也属于格式错误；检查返回要求和原始响应 |
| 修改标准后还是旧行为 | 先保存标准，查看自动准备的消息并保存评测器，再新建复测 |
| 不能删除对象 | 展开引用清单；单对象保护不因归档解除 |
| 全局配置变了，旧任务怎么处理 | 在途任务保持旧连接；旧配置不能复用时用新配置新建复测 |
| 旧版数据在哪里 | v1.1 使用数据根目录下 v1_1/workbench_v1_1.sqlite3，不读取 v0/v1 业务记录；旧文件未删除 |

部署与备份见 [Linux 部署](Linux部署.md)。
