# 独立评测标准与输出模板规范

适用对象：评测任务负责人、标准设计人员和批跑方案配置人员。对应存储修订 4。

## 一、负责人交付内容

每条标准独立提供名称、判断描述、评测方式、需要的原始字段，以及 LLM 输出规则模板或程序规则。标准是项目内独立版本资源，可在多个方案复用。负责人定义业务判断，平台负责发请求、检查结构及保存结果，不汇总业务分数。

建议按以下提纲逐条交付：

1. 名称、目的与适用范围。
2. 判断步骤和证据来源，明确各等级／选项的定义。
3. 缺失材料、不适用、证据不足及边界案例如何输出；如需要“未知”等选项，直接在该标准中定义。
4. 需要的输入字段和字段含义。
5. 输出规则模板。
6. 至少一个正例、反例、信息不足案例，以及期望 JSON 和理由。

同一方案所选标准名称不能重复；名字会成为输出 JSON 的分组键。标准改名需保存新版本并显式更新方案引用，旧方案和运行不会自动改变。

## 二、描述与模板分别填写什么

**标准描述**填写判断规则，例如“只依据给定材料，检查回答事实是否有依据；A 为全部有依据，B 为局部依据不足，C 为关键结论错误。理由需指出具体句子。无材料按 B 处理，不猜测事实。”

**输出规则模板**定义该标准输出的字段名、类型和选项：

```text
{
  "等级": choice:["A", "B", "C"],
  "理由": value:string
}
```

模板不是实际 JSON 答案，不在里面填写判断值。实际答案为：

```json
{
  "等级": "B",
  "理由": "第二段的关键结论在提供的来源中没有依据。"
}
```

## 三、四种规则

| 写法 | 实际 JSON 值 | 约束 |
| --- | --- | --- |
| `choice:["A","B"]` | `"A"` | 字符串，精确选择一个候选项 |
| `multichoice:["缺少来源","事实错误"]` | `["缺少来源"]` | 字符串数组，可为空，不可重复或包含未知项 |
| `value:string` | `"具体说明"` | 自由字符串，结构上允许空字符串 |
| `value:number` | `8.5` | 有限整数或小数，不接受布尔值、数字字符串、NaN 或 Infinity |

每条模板为非空单层对象；全部字段必填，禁止额外字段、空字段名和重复键。单选／多选候选项为非空且不重复的字符串列表。键和值使用 JSON 双引号及转义，例如 `"来源\"说明"`。中文、空格及 `/`、`~` 可用于字段名；导出时路径会正确转义。

不支持手写嵌套对象、可选字段、null、范围、条件规则、尾逗号或执行代码。业务范围和条件写在标准描述中，由模型判断；结构校验仅检查模板定义的类型、字段和候选项。

程序规则不填写 LLM 模板，另设作用字段及规则 Schema。程序业务不通过仍属于执行成功，不触发技术重试。

## 四、不同标准可以不同结构

独立标准“回答质量”：

```text
{"等级":choice:["A","B","C"],"说明":value:string}
```

独立标准“风险检查”：

```text
{"风险标签":multichoice:["缺少来源","事实错误"],"得分":value:number,"说明":value:string}
```

若放入同一执行组，平台生成组合结构，一次模型请求返回：

```json
{
  "回答质量": {"等级":"B","说明":"部分信息不完整"},
  "风险检查": {"风险标签":["缺少来源"],"得分":7.5,"说明":"关键结论缺乏依据"}
}
```

两个“说明”字段在不同标准下隔离。若拆成两组，每组只返回自己的标准分组，独立请求，成功结果合并展示。外层标准键由平台生成，不在单条模板内手写。

## 五、测试、分组与字段

批跑方案页可以用样本预览各组的实际消息和输出结构。需要验证模型结果时，在执行页用实际配置试跑一条，试跑结果保留在批跑历史中。

正式批跑方案选择标准具体版本并分组，新加入默认各自一组，每条标准只出现一次。一个组一次请求，各组独立读原始材料。执行时选择一个数据集并勾选共用字段，个别组可以单独勾选。所有组共用提交时的全局模型和并发上限。

消息变量：`{{criteria}}` 是本组 LLM 标准名称与描述；`{{fields}}` 是本组所选材料；`{{output_instructions}}` 和 `{{response_schema}}` 使用同一份本组组合规则。结构与示例只读，不提供手写整体模板或结果映射。

## 六、校验和失败的含义

响应必须为纯 JSON 对象，拒绝外围解释、代码围栏、重复键和非有限数值。缺少／增加标准、字段错误、类型错误、未知选项、重复多选均使整组技术失败。原响应及可解析内容保留在尝试详情，只有完整校验通过的组写入有效 `output`。同一行其他成功组保留，不因失败组变成低分或空判定。

批跑首轮结束后仅对失败且有额度的组重试，每行每组最多追加 3 次；同组全部标准一起请求，成功组跳过。人工重试和重启不重置额度。试跑和单标准测试不自动重试，取消、重启中断和调度／持久化异常不自动续跑。

## 七、交付与版本管理

保存标准前服务端重新编译模板。保存新版本不影响方案旧引用；方案可查看变化后更新引用，重新保存。标准归档后已有方案会提示不可用，执行前需恢复或替换。运行快照固定分组、每条标准、字段、Schema、消息和模型公开参数，历史始终按当时规则解释。

结果表按执行组／标准／字段显示。XLSX 结果列为 `result/标准名/字段名`，各段 JSON Pointer 转义；数值保持类型，多选为 JSON 文本，并保留完整 JSON 和组状态／错误。JSONL 保留嵌套 `output` 和组级元信息。没有固定四值判定翻译或业务评分统计。
