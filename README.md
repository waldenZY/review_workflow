# Eval Studio v1.1

按项目管理的已有 LLM 内容评测工作台。使用 Python、FastAPI、SQLite 和原生 HTML/CSS/JavaScript，源码直接部署，无需 Node.js 或构建步骤。

**选择项目 → 导入数据 → 选择共同评测字段 → 配置标准 → 编辑消息 → 选择样本执行 → 基本预览 → 导出分析。**

## 启动

Python 3.10+，环境名称不限。当前 Windows 调试使用 moto：

```powershell
$motoPython = 'D:\Application\Anaconda3-5.3.1-Windows-x86_64\envs\moto\python.exe'
& $motoPython -m pip install -r requirements.txt
& $motoPython scripts/start.py
```

Linux：

```bash
python -m pip install -r requirements.txt
python scripts/start.py --host 0.0.0.0 --port 8000 --data-dir "$HOME/eval-studio-data"
```

打开 `http://127.0.0.1:8000` 或服务器地址。页面右上角“使用帮助”可以打开教程，不必离开编辑页；也可直接访问 `/help/tutorial`。API 文档位于 `/docs`。

**已有 v1.1 数据升级**：本次存储结构修订为 2，完整保留业务数据，但必须先停服，运行 `python scripts/migrate_storage.py --data-dir <数据根目录> --check`，确认后执行相同命令的 `--apply`。工具会自动备份整个 `v1_1` 目录并在事务中转换；新版启动不会自动迁移旧结构。详细步骤和回退方式见 [部署说明](docs/Linux部署.md)。本轮尚未执行迁移或运行验收。

## 项目与数据

- 首次先创建项目。项目内分别管理数据集、字段配置、标准方案、评测器、运行和设计调用，不增加任务层级。
- 项目之间不共享、不移动业务对象，接口和存储都检查项目归属。切换项目不会取消后台运行。
- 项目归档后可查看和导出，恢复后才能编辑执行；项目内有未完成任务时不能归档或删除。
- 删除项目先展示对象和文件范围，再输入项目名称确认；单对象删除仍受引用保护。
- 默认数据根目录为仓库外 `../review_workflow_data/`，可用 `--data-dir` 或 `EVAL_DATA_DIR` 指定。v1.1 固定在根目录下创建 `v1_1/workbench_v1_1.sqlite3`，文件在 `v1_1/projects/{project_id}/`。
- v1.1 从空项目开始，不读取、迁移或删除原 v0/v1 业务数据库、项目及上传文件。模型连接文件独立保留。

## 评测和导出

仅导入 JSONL、JSON、XLSX，不支持 CSV。全部标准共用选择的评测字段，不强制区分输入、输出、参考角色。导出专用字段不会自动发送给 Judge 或依据分析。生成任务 Prompt 仅供用户主动提取标准使用。

标准支持 LLM、非空和 JSON Schema。程序规则独立执行；一条记录的 LLM 标准共用一次真实请求。没有产品模拟、演示数据、故障注入、人工复核或回归案例模块。

标准标识自动管理；Judge 只接收启用 LLM 标准的名称和描述，默认按标准名称返回结果。标准名称在同一方案中不能重复。标准与评测器都可复制为新方案草稿。

System/User 必须使用 `{{criteria}}`、`{{fields}}`，返回约束至少包含 `{{output_instructions}}` 或 `{{response_schema}}`。默认发送简洁规则和结构示例，后端继续用完整 Schema 严格校验；自定义结构使用完整 Schema 变量，模板外无隐藏追加。标准保存或切换后自动准备匹配模板，保留用户消息文本；默认返回结构随标准更新，自定义结构保留并提示核对。模板、样本及字段变化自动刷新预览，文本输入约 500ms 防抖，无需手动构建或刷新，不自动保存版本、不调用模型，执行仍使用保存版本。

仅解析纯 JSON 或完整包裹响应的单个 JSON／无语言标记围栏。外围解释文字、语法、Schema、映射错误分别提示，原文与处理过程保留。可评测性分析只对当前样本给建议，不形成执行门禁。

执行与导出在同一页，提供基本预览、取消、失败重试和选中样本新建复测。数据、样本、结果底部支持 10/20/50 条及页码下拉跳转，默认 20。数据和样本表使用紧凑单行及上下联动的横向滚动条，点击内容查看完整值；运行只轮询进度和当前结果页，原始记录及尝试按需读取。XLSX、JSONL 默认保留全部原始列，自定义时始终保留评测字段所属顶层列及额外勾选列。导出包含全部原始行及执行状态，未执行和失败行不会丢弃。

结果表同时展示本次固定的评测字段，支持集中筛选执行异常和按阶段查看错误。整体与本轮重试进度分别显示，执行中和等待保存分开；取消后保留已有结果。存储按行增量保存，分页在数据库完成，导出分批读取。首页按需恢复历史，进度和结果页独立刷新，读取失败自动退避恢复。实现及验证边界见 [性能与运行体验修正](docs/性能与运行体验修正.md)。

## 全局模型设置

页面“模型设置”通过一个下拉框选择配置、一个参数区查看编辑，四个主要按钮为保存修改、使用所选配置、测试连通性、新建配置；其他操作及技术详情折叠。可保存多个命名连接。每份包含八个字段：`api_url`、`api_key`、`model`、`max_tokens`、`timeout`、`stream`、`enable_thinking`、`skip_special_tokens`。地址为完整调用 URL，不追加路径；后两个参数放入 `extra_body`，不自动添加 `response_format`。

“保存修改”写入 `config/llm_config.local.json` 并热加载；“使用所选配置”决定所有项目后续调用用哪一份。编辑当前配置会影响后续调用，在途任务不变。编辑时密钥留空保留同一配置密钥；新建或另存为需显式填写，密钥不回显、不进入业务数据库和导出。示例结构见 `config/llm_config.example.json`，Local 文件已被 Git 忽略。

本项目原八字段文件只在内存识别为“原有配置”，首次用户修改配置文件时原子转换。旧运行失败重试查找它原来绑定的命名配置；切换全局选择无需切回。仅换密钥允许原配置重试，配置删除或公开参数变化则需修正或新建复测。

每份连接另有“批跑执行设置”：`execution.batch_concurrency` 为 1–32 的整数，默认 1，和八个模型调用字段分开保存，不发送给供应商。一个运行内部可并发，不同运行仍按提交顺序排队；纯程序规则串行。运行固定提交时并发数，原配置重试沿用旧值，新建复测用当前值。并发数不参与模型指纹，运行详情及 XLSX/JSONL 导出单独记录 `execution_config`。

并发数控制同时处理的记录数，不是每秒请求数。单条试评仍只评一条，不会为凑并发重复调用。取消停止派发新记录，等待在途请求结束并保存后结束任务，未派发记录保持未执行；限流等技术失败保留，不自动重试或降并发。

保存和启动不会探测模型。“测试连接”单独触发短请求，不自动保存、不验证评测质量。没有有效配置仍可管理项目、编辑和预览，纯程序规则可执行；需要模型的操作会明确阻止。

## 文档与验收

### 历史与配置管理（2026-11-09）

历史页聚焦评测运行，按时间、数据集、状态和处理数量展示，支持分页与筛选。详情在独立弹窗中查看结果、完整配置快照、原始记录、请求响应及重试轮次，查看历史不切换当前业务草稿。可原配置失败重试、按原配置新建运行（全部原样本或勾选子集）、载入配置并编辑，以及导出和删除。

数据集、所属命名字段方案、标准、评测器在各自页面通过“管理”查看版本、载入、归档、恢复和删除。标准页管理设计调用。保存新版本延续原方案，另存为创建独立方案；评测器可复用到当前标准的新草稿，自定义结构和映射保留并核对。历史载入编辑恢复为新方案草稿，依次保存后执行，原运行不变；原配置新建运行保留原模型与并发，载入编辑后执行使用当前全局模型。
