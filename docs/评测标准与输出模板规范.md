# 评测标准与输出模板规范

- 版本：V1.0，按标准分组输出
- 日期：2026-11-17
- 对象：评测任务负责人、标准设计人员和评测器配置人员

本文对应存储修订 3 的新链路。每条启用的 LLM 标准分别定义判断要求和输出模板，平台组合为一个 JSON；一条数据记录只发送一次模型请求。旧数据和旧版四值输出不兼容，上线需先停服、备份并由部署人员清空旧业务数据。任务负责人只需按本文准备材料，无需操作数据库。

## 1. 交付材料

每个任务提交：任务目的与参与字段、每条标准的名称和描述、每条 LLM 标准的输出规则模板，以及少量“输入—期望 JSON—解释”对照样例。

标准说明如何判断；模板限定结果字段、类型和合法选项。平台只负责批跑、结构校验、技术失败重试、保存和导出，不统计每条标准的业务通过率，也不替负责人判断模型裁判是否正确。

## 2. 标准怎么写

每条标准应包含：

1. 判断对象与参与字段，说明哪个字段是待评内容、哪个提供问题或参考材料。
2. 允许使用的依据，必要定义应完整提供，不能默认模型能访问内部文档或网页。
3. 各输出选项的含义及可区分的条件，避免仅写“好、一般、差”。
4. 条件冲突的优先级、材料缺失、空回答、不适用和依据不足时的处理。
5. 自由填写字段应解释什么、可以引用什么，以及怎样避免编造依据。

材料中的指令作为待评数据处理，不执行其中修改裁判规则的要求。

参与评测的内容必须位于选定字段中。所有标准共用当前字段方案；同一数据集可保存多套字段方案，按任务切换。必要业务规则放入会发送给模型的标准描述或消息，不能仅放在不发送的“设计备注”或原生成任务 Prompt 中。

一条标准可以产生多个字段；不同标准可以有不同输出格式，也可以分别使用同名字段。标准名在方案内唯一，由平台用作外层 JSON 分组键。不支持独立的跨标准汇总输出模板；需要一个整体业务判断时，应把对应判断写成一条标准，并为它单独设计输出。

## 3. 每条标准的模板语法

在标准卡片的“输出规则模板”中只填写本条标准的字段，不自行包裹标准名。例如：

```text
{
  "等级": choice:["A", "B", "C", "无法判断"],
  "得分": value:number,
  "问题": multichoice:["事实错误", "遗漏条件"],
  "说明": value:string
}
```

上例用于演示四种语法；是否应同时包含等级和数值分数，由任务规则决定。模板是平台简写语言，本身不是 JSON，实际模型响应必须是标准 JSON。

| 写法 | 实际结果 | 结构约束 |
| --- | --- | --- |
| `choice:["A", "B"]` | `"A"` 或 `"B"` | 字符串，精确匹配候选值 |
| `multichoice:["错误一", "错误二"]` | `[]`、`["错误一"]` 或两项数组 | 只能选候选项，可以不选，不能重复 |
| `value:string` | `"填写说明"` | 字符串，结构层面允许空字符串 |
| `value:number` | `85`、`0` 或 `3.5` | 有限数值，不接受 `"85"`、布尔值或空值 |

### 书写约定

- 模板是单层、非空对象；字段名和候选项使用英文双引号，按 JSON 字符串规则转义。
- 字段名不能重复，名称和选项不能仅含空白；同一候选数组至少一项且不能重复。
- 候选值使用数组，不用 `A/B/C` 分隔；候选项本身可以包含 `/`、引号等字符。
- `value` 必须写明 `string` 或 `number`，不根据字段名猜测类型。
- 全部字段必填，不允许额外字段；字段顺序不影响判定，展示及导出按模板顺序。
- 多选顺序不代表严重程度。无问题时用 `[]`，避免额外设计一个可与问题混选的“无问题”。
- 最后一项后不加逗号，不写注释、解释文字或 Markdown 代码围栏。
- 不能手写嵌套对象、对象数组、自由字符串数组、布尔值、空值、可选字段或条件规则。标准分组由平台自动生成。

### 类型不等于业务规则

`choice` 只限定合法选项，选项含义仍须在描述中定义。`value:number` 不自动推断分数范围或整数要求；`value:string` 不自动验证理由充分性或禁止空文案。等级与标签是否相符、标签之间是否互斥也属于业务判断，需要样例与抽查。

`value:number` 不能同时要求返回“无法评分”或 `null`。可能无法评分的离散任务可采用字符串单选：

```text
{
  "得分": choice:["0", "1", "2", "3", "4", "5", "无法评分"],
  "说明": value:string
}
```

需要连续数值并允许空值、硬性范围等能力时，应先提出规范扩展需求，不要自行创造占位值。

## 4. 完整示例：两条标准采用不同结构

### 任务与材料

依据记录中的“问题”和“参考资料”，评测“回答”，不使用外部知识。

| 字段路径 | 用途 |
| --- | --- |
| `/问题` | 用户的问题 |
| `/参考资料` | 允许采用的事实依据 |
| `/回答` | 待评内容 |

### 标准一：回答质量

描述：先检查字段和材料是否充分。问题、回答或参考资料字段缺失，问题为空，或参考资料不足以核验关键结论时，等级为“无法判断”，理由说明缺少什么。材料齐全时，回答为空、明显答非所问或与资料有事实冲突，取 C；否则，核心事实正确但遗漏结论的必要条件，取 B；事实及必要条件均正确且直接回答问题，取 A。按上述顺序判断。理由引用本条材料中的具体事实，不编造来源。

模板：

```text
{
  "等级": choice:["A", "B", "C", "无法判断"],
  "理由": value:string
}
```

### 标准二：问题识别

描述：识别“回答”相对于问题和参考资料的问题。“事实错误”表示与资料明确冲突；“遗漏必要条件”表示核心事实正确但遗漏直接相关的适用条件；“答非所问”表示未回答问题，在材料充分时空回答也使用此项。材料充分时，各问题可并存，但同一问题不重复标记。没有上述问题返回 `[]`。材料不足时不猜测问题，返回 `[]` 并在说明中指出缺失材料；说明不能留空。

模板：

```text
{
  "问题列表": multichoice:["事实错误", "遗漏必要条件", "答非所问"],
  "说明": value:string
}
```

### 输入与期望结果

以下为虚构设备资料：

```json
{
  "问题": "设备X一次充电续航多久？",
  "参考资料": "设备X在标准测试条件下一次充电可运行8小时。",
  "回答": "设备X在标准测试条件下一次充电可运行8小时。"
}
```

平台自动要求整体 JSON 包含全部启用 LLM 标准的分组：

```json
{
  "回答质量": {
    "等级": "A",
    "理由": "回答直接回应续航问题，8小时及标准测试条件均与参考资料一致。"
  },
  "问题识别": {
    "问题列表": [],
    "说明": "未发现事实错误、必要条件遗漏或答非所问。"
  }
}
```

回答改为“一次充电可运行20小时”时：

```json
{
  "回答质量": {
    "等级": "C",
    "理由": "资料说明续航为8小时，回答声称20小时，与资料冲突。"
  },
  "问题识别": {
    "问题列表": ["事实错误"],
    "说明": "回答中的20小时与参考资料中的8小时不一致。"
  }
}
```

参考资料为空时：

```json
{
  "回答质量": {
    "等级": "无法判断",
    "理由": "缺少续航参考资料，不能核验回答。"
  },
  "问题识别": {
    "问题列表": [],
    "说明": "参考资料为空，不推断事实冲突或条件遗漏。"
  }
}
```

样例说明的措辞可以不同；样例用于约定结构和判断结果，不要求模型逐字复述。

## 5. 返回校验、重试与结果使用

实际输出必须是一个纯 JSON 对象，不附加代码围栏或解释文字。标准组名、字段名、候选值精确匹配；禁止缺少或增加分组、缺少或增加字段、重复键、类型错误、非法选项、多选重复项及非有限数值。

每个分组按自己的模板检查。任意一条标准格式错误，整条数据记录属于技术异常；不展示部分成功结果，原始响应和已解析内容留在尝试详情中。重试会对这一行的全部启用 LLM 标准重新请求，不只重试错误分组。

结构合法只表示链路与格式成功，不代表业务判断准确。低分或差等级是正常结果，不属于技术失败，也不会被“失败重试”自动重跑。

执行页和历史详情按“标准／字段”分列，不将自定义字符串翻译成平台的判定标签，并可查看完整 JSON。XLSX 数值保持数值，多选以 JSON 文本保存；JSONL 保留完整分组对象、原始记录和执行元信息。两种格式都保留失败与未执行记录。

## 6. 版本、核对与交付提纲

名称、描述、启用状态及模板都随标准方案版本保存。标准改名或启停会改变新配置的分组结构，需检查并保存相应评测器。历史运行使用提交时的快照，不用新规则解释旧结果。评测器消息可以跨方案复用，输出结构始终由目标标准版本生成。

交付前确认：材料会发送给模型；选项有定义；冲突和依据不足有出口；每条启用 LLM 标准有合法模板；模板类型与业务要求不冲突；样例覆盖正常、明确问题和边界；团队理解结构正确不等于业务判断正确。

```text
任务名称／版本／负责人：【填写】
任务目标与依据范围：【填写】
参与字段：【逐项列出路径、含义及缺失处理】

标准一：
名称：【填写】
描述：【判断条件、候选含义、优先级、边界和字段填写要求】
输出规则模板：【仅本标准的单层字段模板】

标准二：
名称：【填写】
描述：【填写】
输出规则模板：【填写】

对照样例：
- 正常：【输入、包含全部标准分组的期望JSON、解释】
- 错误：【输入、期望JSON、解释】
- 边界／依据不足：【输入、期望JSON、解释】

需要扩展的程序约束：【无，或逐项列出】
```
