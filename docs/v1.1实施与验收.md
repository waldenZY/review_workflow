# v1.1 实施与验收

日期：2026-10-30。需求来源：[Issue #2](https://github.com/waldenZY/review_workflow/issues/2) 及本轮确认的修改计划。

## 本轮实施

- 保持 Python、FastAPI、SQLite 和原生前端，不引入 Node.js 部署依赖、产品模拟或自动测试。
- 数据根目录固定追加 `v1_1/`，使用 `workbench_v1_1.sqlite3` 和独立项目文件；启动时才创建，不读取或清理旧版业务记录。
- 标准内部标识由系统自动生成，编辑已有标准时保留；界面只读序号，同一方案标准名称不可重复。复制方案保存为独立新对象。
- Judge 只收到启用 LLM 标准的名称和描述。默认按名称返回，JSON Pointer 自动转义名称中的 `/`、`~`，结果继续关联内部标识。
- 默认模板使用 `criteria`、`fields`、`output_instructions`；简洁规则与示例替代重复的完整 Schema，后端仍严格校验。自定义 Schema 使用 `response_schema`，避免默认格式说明与自定义结构冲突。
- 草稿预览读取当前模板、Schema、映射和评测字段，不保存、不调用模型；修改延迟约 500ms 刷新，项目 epoch 和独立预览序号拒绝迟到响应。
- 三处分页默认 20，可选 10/20/50，底部提供页码下拉跳转。数据和样本表采用紧凑单行及上下联动横向滚动条，点击内容查看完整值，数据列高亮关联选中路径。运行页仅轮询状态和分页摘要，记录及历次响应按需读取。
- 保留两级归档、只读规则、恢复和引用保护，操作收进“更多操作”；归档不级联。标准及评测器可复制为未保存草稿。
- 模型配置通过单个下拉框加载、参数区编辑，主要操作为保存修改、使用所选配置、测试连通性和新建配置；另存为、删除、清除密钥在更多操作。保存和启用分开，已提交任务持有不可变连接。原配置重试查找绑定配置，不依赖全局当前选择。
- 可评测性建议只基于当前样本，逐标准展示缺失、影响和建议；不会修改标准的未保存状态或形成门禁。

## 解析边界

接受纯 JSON，或完整包裹响应的单个 JSON／无语言标记围栏，允许首尾空白及 BOM。围栏外解释文字、多围栏及不完整围栏均失败，不截取，不调用模型修复。合法 JSON 字符串内的反引号属于材料内容，不误判为外围围栏。

统一记录 raw_output、normalized_output、normalization、error_stage 和 error，区分外围格式、原文或剥离围栏后的语法、Schema 及投影错误。重复 JSON 对象键和非有限数值也明确拒绝，避免同名标准结果被静默覆盖。

## 配置与接口

全局 `config/llm_config.local.json` 保存 `schema_version: 2`、`active_profile_id` 和 `profiles` 数组；每项包含 `id`、`name`、八字段 `config` 及独立的 `execution.batch_concurrency`（1–32，默认 1）。现有配置缺少 execution 时只在内存补默认值，下一次用户配置写入时持久化。文件不入 Git。原八字段格式仅内存识别为“原有配置”，用户第一次配置写入时原子转换；本轮未读取或修改实际 Local 文件。

| 接口 | 用途 |
| --- | --- |
| GET `/api/v1/llm/status`、`/api/v1/llm/profiles` | 脱敏状态及命名配置列表 |
| POST `/api/v1/llm/profiles` | 创建，不自动启用 |
| PUT/DELETE `/api/v1/llm/profiles/{id}` | 修改或删除；删除当前配置后不自动选择其他配置 |
| POST `/api/v1/llm/profiles/{id}/activate` | 启用，影响所有项目后续调用 |
| POST `/api/v1/llm/profiles/{id}/clear-key` | 清除此配置密钥 |
| POST `/api/v1/llm/test` | 明确按钮触发，使用表单，可带 profile_id 沿用该配置密钥，不保存、不启用 |

项目接口前缀保持 `/api/v1/projects/{project_id}`：

| 项目内路径 | 用途 |
| --- | --- |
| POST `/requests/preview` | 保存版本静态预览 |
| POST `/requests/preview-draft` | 当前评测器草稿预览，校验数据与标准归属，不产生对象或版本 |
| GET `/runs/{id}` | 运行摘要、版本引用、原始列名和导出登记，不包含原始行或尝试正文 |
| GET `/runs/{id}/progress` | 状态与进度 |
| GET `/runs/{id}/records?offset=0&limit=20` | 当前页结果摘要，不含请求及原始响应 |
| GET `/runs/{id}/records/{row_id}` | 单条原始记录与历次尝试 |
| GET `/runs/{id}/configuration` | 完整业务配置和已选行 ID，不包含原始数据行 |

密钥不回显、不入业务数据库或导出。所有命名配置的密钥参与脱敏，已删除或轮换密钥在当前进程内继续参与脱敏。运行记录配置 ID、名称和公开指纹，指纹不包含名称、ID 或密钥；仅轮换密钥不阻止原配置重试。绑定配置缺失、无密钥或公开参数不匹配时拒绝重试，不回退到全局当前配置。

## 补充：可配置批跑并发

- 配置创建、修改接口增加 `execution`，查询返回各配置及当前配置的执行设置。原八字段 HTTP 参数保持独立，连接测试不接收并发设置。
- 配置锁内捕获不可变连接及并发元数据；运行提交时写入独立 `snapshot.execution_config`，运行摘要、配置详情、XLSX/JSONL 及导出清单均保留本次并发数。
- 原配置重试从原快照读取并发数，新建复测采用提交时的全局设置；并发数不参与连接公开指纹，不改变密钥和模型参数的原有校验。
- 单个 FIFO 运行队列，当前运行内部使用标准库线程池，有界补位而非一次提交全部记录。纯程序规则上限固定 1。
- 调度线程通过行 ID 在数据库锁内增量保存；HTTP 等待不持锁，工作线程不写数据库。完成结果先保存再补位，结果乱序完成不改变展示和导出的源行序。
- 取消与派发共用存储锁，取消后不再派发；收集在途结果后结束，未派发记录保持 pending（页面显示未执行）。单条返回的技术失败不终止其他记录、不自动重试。
- 调度异常停止新派发，收集已发结果并标记运行异常；未知调用状态不伪装成已调用或未调用。关闭标志与保存共用锁，防止数据库关闭后迟到写入；重启中断规则保留。
- 进度新增 `running`、`pending` 数量，`processed` 仍包含技术失败。设置页显示批跑执行设置，运行页显示固定并发数、执行中和待执行／未执行数量。

本次没有启动服务、调用模型或新建自动测试。以下并发运行行为仅完成源码检查，尚未实测：默认串行、并发上限与补位、两次运行排队、乱序完成后的行序、单条失败继续、取消收尾、原配置重试及关闭／重启。单条样本不能证明真实并发能力，不借用旧版本验收记录作为通过证据，后续由用户明确安排小批量验收。

## 补充：界面与交互修正（2026-10-30）

本次沿用当前存储与连接配置，没有迁移、清理或重建业务数据，不改变评测和并发规则。

- 查找、分页等控件统一 32px 行内布局。三处分页只保留底部一组，页码下拉收起显示当前页，选中即跳转；每页数量变化回第一页，跨页勾选保留。数据页只在请求成功后更新页码，运行页把目标页与确认页分开，防止轮询冲回旧页；失败保留上次成功内容。
- 数据与样本表上下提供同步横向滚动条，溢出时显示，尺寸变化后重算并限制有效滚动位置。单行截断、行高约 28px，点击单元格打开完整值面板；查看内容不勾选样本。具体嵌套路径在列头提示中查看。
- 标准卡片分为名称行、固定操作行及描述区，启用、160px 方式选择器、删除不拆散换行，窄屏允许操作行横向滚动。
- 标准保存／选择版本及进入评测器页时自动准备模板，不需要构建按钮。匹配查询包含评测器全部保存版本，优先最近选择，再选最近匹配对象，否则生成默认草稿。不会自动创建版本或模型调用。
- 同一方案标准更新后保留 System／User 文本，原 Schema 和映射均为默认时更新为新默认结构；自定义返回配置保留并提示核对，手动示例保留且不合法时提示修正。同步请求晚于用户编辑返回时不覆盖新编辑。
- 标准草稿未保存时预览仍使用保存标准。模板、字段和样本变化自动预览，约 500ms 防抖；无样本时默认当前数据页第一条。条件不满足就地说明。历史运行加载及归档历史不自动升级绑定。
- 评测器选择和新建紧凑排列，标准／版本小字显示。Schema、映射、示例、复制、恢复默认和版本放高级设置；恢复默认提示替换未保存内容。
- 模型页取消列表表格和重复状态块，保留一个配置下拉、一个参数区及四个主要按钮。选择只加载，不自动启用；删除、另存为、清除密钥和重新读取放更多操作，指纹和原始测试响应折叠。

接口变化：GET `/api/v1/projects/{project_id}/evaluators/matching?spec_id=…&spec_version=…` 返回项目内匹配的未归档评测器版本元数据；POST `…/evaluators/build` 增加可选 `source`（评测器草稿），在服务端比较来源版本的默认结构，返回未保存草稿、结构示例及同步提示。两条接口均校验项目与版本归属；分页继续使用已有 offset/limit 接口。

本次已执行 Python 编译、JavaScript 语法、OpenAPI 定义生成、文档及差异静态检查，没有新增自动测试、模型请求或业务样本。没有进行浏览器视觉／交互验收，不将 CSS 中的尺寸或事件逻辑写作实测结果。

待人工验收：宽窄屏控件对齐、上下滚动条联动、28px 紧凑行和内容面板、页码跳转及失败回退、轮询与页码请求交错、自动准备与自定义模板保留、历史版本不升级、自动预览与草稿保护、模型配置四个主要操作。浏览器当前不可用，以上项目如实保留待确认。

## 补充：全局控件高度及对齐复查

检查后统一 XLSX 工作表／表头行、已保存字段配置、标准和评测器的版本 A／B、历史对象类型工具栏为行内标签，避免上下标签把相邻按钮的对齐基准抬高。标准输入框、选择器、按钮和“更多操作”使用同一个 32px 高度变量及 20px 行高，复选项的点击区域至少为 32px；顶部帮助按钮也使用标准规格。26px 小按钮只用于帮助面板、内容面板等独立辅助区。

未改变字段含义、保存逻辑、模型设置、运行或数据。已做源码和静态语法检查；浏览器不可用，实际像素、窄屏换行和控件基线仍需人工确认。服务重启仅用于加载页面并供用户试用，不自动触发模型请求。
