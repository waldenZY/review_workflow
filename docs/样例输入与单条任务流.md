## 2. 当前记录能提供什么

首条 JSONL 记录的字段如下。角色是针对本例的候选解释，最终需要用户映射确认。

| 字段 | 观察到的形态 | 候选角色 |
| --- | --- | --- |
| sample_id | 字符串，首条为 Q0001 | 外部定位 ID；不能代替内部唯一 row_id |
| source_batch / source_row | 字符串 / 数字 | 来源信息，默认不传给 Judge |
| sample_type | 字符串 | 可选输入上下文 |
| context_text | 首条为空字符串 | 可选上下文；不等同于缺少所有任务输入 |
| target_query | 字符串 | 任务输入的一部分 |
| conversation_turns | 字符串数组 | 保留有序数组；在本例中可作为主要输入 |
| candidate_category | 对象，含 L1/L2，首条均为 null | 待原生成任务处理的输入，不是人工确认的参考标签 |

首条记录没有“按所给生成 Prompt 已经生成的结果”字段，也没有人工确认的参考答案。本轮不能据此断言所有行或 XLSX 都相同。

`context_text`、`target_query` 和 `conversation_turns` 可能表达相关信息，不能默认全部重复拼接进请求；映射预览应让用户选择。

## 3. 分清本例的两层任务

提供的生成 Prompt 描述一个质检标注任务：对输入给出五项标签。它要求的五项 JSON 是**原任务的生成输出格式**，不是新工作台必须采用的评测输出格式。

| 层级 | 输入 | 输出 | 本阶段是否负责执行 |
| --- | --- | --- | --- |
| 原生成任务 | 样本信息与生成 Prompt | 五项业务标签 | 否；已有输出应由数据导入 |
| 工作台评测 | 已有业务标签、原输入、确认后的标准和可用依据 | 标准判定、证据、执行记录及用户定义的结果载荷 | 是；当前尚未实现 |

本例中，业务标签的 `validity=invalid` 可能是正确的生成结果。不能直接将其统计为“生成质量不合格”；工作台需要判断该标签是否符合标准和当前输入证据。

同样，不能为了试评而直接执行生成 Prompt，把新生成的五项标签当作工作台评测结果。这会混淆生成和评测，偏离模式 A。

## 4. 一条样本如何走通

以下是后续实现路径，并非本轮运行记录。

1. **导入与定位**：选择一条记录，分配内部 row_id，保留原始字段及来源。
2. **补足已有输出**：通过导入或手动粘贴一份已有生成结果，将其映射为待评测输出。本例当前只观察到任务输入，界面应明确提示缺少该角色。
3. **配置标准**：用户手动输入；或者将生成 Prompt 作为分析资料，提取候选标准后人工编辑确认。提取不执行原生成任务，不自动把其中的格式例子当成正确答案。
4. **分析依据**：区分能直接验证的结构要求、可由输入支持的语义判断，以及缺少参考而无法充分判断的要求；逐条展示风险。
5. **构建评测器**：将标准绑定至内置规则或 LLM Judge；配置模型、返回结构及标准结果映射，不执行模型生成的任意代码。
6. **预览请求**：显示实际使用的字段、标准及请求，区分原始任务资料和评测指令，避免因样本文本改变执行流程。
7. **选一条试评**：明确选中 row_id，只运行该条；保存请求、原始响应、解析/校验结果、版本及使用量。
8. **人工复核**：对照输入、已有输出与判定依据记录修订；保留 Judge 原结论，人工确认后可存为回归案例。
9. **导出**：保留原列，新增独立评测列及执行状态；不修改业务输出，不把未运行行记成失败。

## 5. 当前缺少输出时如何做工程演示

无需为本轮补跑生成任务。后续若要先验证页面、请求拼接和导出，可以为同一条记录另行建立明确标注的模拟输出副本；如同时使用模拟 Judge，二者来源需分别记录。

模拟数据不覆盖 `testdata/`，不作为正确标签，不加入人工验证案例，也不计入任何准确性结论。当前尚未创建此类模拟数据或调用任何模型。

真正验证评测能力时，使用已有生成输出；验证判断是否正确时，再增加人工确认依据或标签。一条样本只用于当前流程连通性检查。

## 6. 通用能力与示例配置的分界

通用能力包括：嵌套字段映射、多字段角色、输出结构校验、标准与依据管理、可追踪的一条试评及导出。

本例中的字段名、五项标签、枚举、准入条件和业务判断逻辑，只能出现在示例方案中；不能成为产品固定页面、内部判定枚举、默认标准或全局规则。生成任务占位符 `{CANDIDATE_JSON}` 也不成为通用系统强制使用的模板变量。
