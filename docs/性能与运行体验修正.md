# 性能与运行体验修正

本轮继续使用 v1.1 数据目录，数据库结构修订号为 2（SQLite `user_version`），不是再次建立空业务库。目标是结果材料对照、异常集中查看、轮次重试、轻量加载、逐行保存及明确并发状态。

## 存储与读取

- `entities` 保留原对象及版本，新增独立摘要；数据集正文移除 rows，引用不可变材料。
- `materials` / `data_rows` 保存材料指纹、顶层列顺序及逐行原始 JSON。指纹包含行 ID、源行号、内容和原始顺序。历史快照与当前数据集不同则独立保存，不按数据集 ID 强行合并。
- `runs` 仅保存固定配置、小型状态正文、列表摘要及进度计数；`run_records` 保存所选行状态与最新结果摘要，`attempts` 保存完整调用，`attempt_metrics` 单独补充提交完成后测得的保存耗时。
- `run_rounds` 保存新执行及重试的范围归属、类型、时间和计数；各行归属轮次，attempt 记录其执行轮次。旧历史不能可靠还原时留空，页面显示未记录。
- `object_refs` 索引跨对象引用，历史、删除和归档检查不扫描所有材料和响应。删除数据集时，所属字段配置的外部引用也会阻止删除。
- 数据与结果由 SQL 分页；逐条处理仅读取当前行，状态和 attempt 以短事务更新。进度直接读取计数，不汇总整个运行正文。
- 一个写连接及短写锁；读取用独立只读连接与短快照，忙等待上限 5 秒。数据库错误返回 503 / `storage_unavailable`，不包含 SQL 内容或密钥。
- 导出按 100 行一批读取，JSONL 顺序写入、XLSX 使用 write-only 工作簿。轻量导出租约阻止同一运行重试／删除及所属项目删除，整个导出不持有写事务。

## 执行与接口

不同运行仍排队，同运行仍以快照并发上限控制。线程池内执行请求及解析；完成一条后持久化并补位，再处理其他已完成结果。“执行中＋等待保存”不超过上限，不设置无界响应队列。每个运行复用自己的 HTTP 连接池和固定连接配置。

取消不删除结果：后端受理后停止派发，排空在途工作和保存结果，最终允许导出。页面提交动作与后端取消状态分开。关闭后不接受迟到写入，重启按中断处理，不自动请求模型。

重试在原运行创建新轮次，只选未完成、技术失败或中断行；执行成功但内容不通过的行不自动重跑。继续遵守原配置指纹、密钥和固定并发规则。新建复测仍创建关联的新运行。

| 项目化接口 | 变化 |
| --- | --- |
| `GET …/runs/{id}` / `…/progress` | 增加整体成功数、`round_progress`、`current_round`、`updated_at` 和 `stage_counts`；进度只读摘要 |
| `GET …/runs/{id}/rounds` | 查询可追溯轮次；旧历史可能没有轮次 |
| `GET …/runs/{id}/records` | 保留 offset / limit，新增 `status_group=all\|errors\|pending`；错误组支持 error_stage |
| 同上 | 当前页增加固定评测字段值、缺失路径、结果所属轮次及是否为上次尝试；总数为筛选后的总数 |
| `GET …/runs/{id}/records/{row_id}` | 按需读取原记录及历次尝试，附阶段耗时；不由轮询自动获取 |

`stage_counts.executing` 包括请求、读取材料和解析，`saving` 表示等待持久化，并非两个网络连接计数。瞬时阶段来自有界内存状态，重启失效；已持久化计数来自数据库。每个运行维护内存阶段递增序号，读取数据库进度前后核对序号及活动总数，最多采集两次。仍不一致时阶段数量返回 null 并标为更新中，不裁剪或推算为 0；不会为此持有全程写锁。

阶段耗时以单调时钟计算：运行排队、从本轮开始等待派发、worker 等待及读取材料、请求、解析校验、等待保存、写锁等待、保存事务（包括主结果提交）。主事务提交后得到的保存耗时先进入最多 32 条的有界缓存，由下一次补位、保存、取消或结束等业务事务顺便写入已有指标表，不再单独提交。指标写入使用保存点隔离，提交成功后才移除缓存；回滚保留待写值，溢出仅丢弃最旧指标并输出脱敏警告。正常结束事务保存最后一条指标；异常退出允许少量指标未记录，不为指标补写突破关闭保护。详情可补充缓存中已测得但尚未落库的指标。未知或历史未记录的耗时不补造，各阶段存在包含关系，不能直接全部相加。

## 页面行为

- 首页健康检查后即可操作，模型设置和项目列表独立加载；进入项目模块时才恢复相关数据、配置和运行。
- 结果列按该运行固定字段显示材料，点击查看完整值，支持上下横向滚动；不受当前编辑草稿影响。
- 异常筛选由服务端覆盖整个运行，内容不通过不归类为技术异常；筛选不改变导出范围。
- 当前轮与整体进度分别显示；旧结论／错误明确标为上次尝试。详情先展示状态、阶段、错误和时间，原始请求及响应折叠。
- 普通 GET 超时 15 秒。健康检查和项目目录等失败有阶段提示及手动重试；上传、导出和设计调用不使用这个短超时。
- 进度轮询每 2 秒一次，失败后按 2 / 4 / 8 / 15 秒退避，随后间隔最多 15 秒。结果页独立请求，页码、筛选及最近成功页面保留。
- 展示上次进度和结果页读取时间；过期响应按项目及请求序号丢弃。自动恢复仅重复读取，不重新提交取消、重试、批跑或模型调用。

## 补充修正：收尾、局部更新和指标开销（2026-11-03）

在当前结构修订 2 上继续修改，无新表或迁移，不改变完整字段值返回、评测、取消与导出语义。

- 结果读取以每个当前运行一个活动请求、一个合并刷新标记串行工作。请求固定项目、运行、轮次、视图版本、页码、页大小和筛选；旧响应和旧 finally 不覆盖新状态。
- 确认终态后另发结果查询。此前发出的查询不能完成最终收尾；查询失败明确显示“任务已结束，最终结果页尚未更新”，保留最近成功内容并提供重试。离开运行页时仅保留刷新需求，返回后执行。
- 进度仅局部更新状态、计数、时间、进度条和相关按钮；结果按稳定行 ID 更新当前页，未变化行保留 DOM，变化行也保留其材料和详情节点。轮询不调用根页面 render，不重复构建大段详情；翻页、勾选、筛选、焦点和滚动尽量保留。
- 请求、响应、规范化正文、解析载荷和耗时，在相应折叠区首次展开时格式化为文本节点。相同 attempt 的已生成 DOM 可复用；记录新增结果时仅提示详情过期，不自动获取或格式化。
- 详情缓存按最近使用回收，目标最多 10 条记录或估算 10MiB（含格式化文本）。打开的记录不强制关闭，关闭后回收；离开当前结果页的记录视为未打开。切换项目或运行清空缓存。
- 首页项目和模型配置分别维护加载、成功、失败状态，并在各自返回时立即更新对应区域。项目加载中不显示没有项目，失败各有重试入口。递增请求号和编辑修订号防止后返回的初始化读取覆盖用户选择或草稿。
- `stage_counts` 新增 `consistent` 和 `observed_at`；不一致时 `executing` / `saving` 为 null，页面显示更新中。整体与当前轮次计数继续显示，不将阶段更新误解为无请求。
- 耗时指标随业务事务合并写入，主结果保存不再额外开启一次指标事务；现有指标仍兼容读取。此项不改变数据库版本。

完整字段仍随当前页传输，完整内容查看不增加截断接口或大小限制。大字段的网络、JSON解析和显式查看开销仍存在，不保证所有容量下无卡顿。

本补充轮保持服务关闭，仅做静态检查，没有调用模型、运行评测、迁移数据库或新增自动测试。此前按用户要求的本地预览启动仅说明基础页面/API可用，不证明本补充的收尾、缓存或容量效果。具体交互、并发及慢磁盘效果仍待另行运行验收。
